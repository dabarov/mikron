How Mikron measures any web page without changing it

Mikron is a Chrome extension I built for reading the spacing of a page. Hold Shift, drag a box over any area, and that area is redrawn as a blueprint: padding and gaps as hatched bands with their values, a size chip on each box, an arc on rounded corners. One click copies the numbers as text.

You can try it without installing: the project page runs the extension's own code on a sample card. This page is about the parts that took longer than I expected.

The gesture has to be invisible until you want it

A content script on every page that reacts to Shift is a good way to annoy people. Shift is used for capitals, for extending a text selection and for half the shortcuts in any web app. So several things have to be true before anything shows:

  • Shift has to be held for 250 ms, and the pointer has to move 4 px after that. Only then does the cursor become a crosshair.
  • Any other key pressed while Shift is down cancels the attempt, so Shift+letter and Shift+Tab never arm it.
  • A press on an input, a code editor, a map, a canvas, a video or anything draggable never starts a selection.
  • If the page calls preventDefault() on pointerdown, or captures the pointer, the page owns the press and Mikron backs off.
  • Under 6 px of travel the press is a plain click, and Mikron replays what the browser would have done, such as extending the text selection.

The rule I ended up with: a plain click never changes anything.

Reading layout without changing it

When you drag, Mikron walks the DOM under the selection and builds a model: one node per element, with its border box, padding, border, radius, text lines and gaps. Everything comes from three read-only calls: getBoundingClientRect(), getComputedStyle(), and Range.getClientRects() for text.

Three things made this harder than it sounds.

Transforms and zoom

getBoundingClientRect() returns on-screen pixels. On a card scaled to 0.8, a 16 px padding measures as 12.8. The number a developer wants is the one written in the CSS, so each element gets a scale factor and every value is divided by it. Simplified:

const rect = el.getBoundingClientRect();
const scale = el.offsetWidth ? rect.width / el.offsetWidth : 1;
const cssWidth = rect.width / scale;

Rotated and skewed elements get no padding bands or radius callouts, because a band on a rotated box is no longer a rectangle.

Gaps

The space between two siblings can come from gap, from margins or from justify-content: space-between. Reading the gap property covers one of those. Mikron measures the distance between the rendered boxes of the children instead, so the number is what you see, whatever produced it.

Text

A paragraph is one element but several lines. A Range over the text gives one rectangle per line fragment, and the grey bars in the blueprint are drawn from those.

The scan has a budget: the viewport plus a 300 px margin, and 1500 nodes or 40 ms, whichever comes first. If it runs out, the size label says "partial" and the copied spec starts with a note, so a cut-off result is never presented as complete.

Names a person can read

Each line of the copied spec starts with a name such as button.btn or li.row. On a site built with utility classes or CSS-in-JS, the raw class list is noise: flex items-center px-4 css-1x2y3z. Mikron drops generated prefixes (css-, sc-, jsx-, svelte-) and layout utilities (flex-, px-, text-, bg- and so on), keeps at most two classes, and caps the name at 40 characters.

Drawing over a page you do not own

The overlay lives in a shadow root on a custom element, so page styles cannot reach it and its styles cannot leak out. The scanner skips that element; otherwise Mikron would measure its own chips.

The chips use a bundled monospace font, and loading it was a small puzzle. Chrome ignores @font-face inside a shadow root, and a rule injected into the page is subject to the page's Content Security Policy. So the service worker reads the font file from the package, hands the bytes to the content script, and the script registers them with new FontFace(name, arrayBuffer). No CSP directive applies to a binary source. If anything fails, the chips fall back to the system monospace font.

Copying without a clipboard permission

Mikron has no clipboardWrite permission. The Copy click is a user gesture, so the content script calls document.execCommand('copy') and fills the clipboard in its own copy listener. Simplified:

window.addEventListener('copy', (e) => {
  e.clipboardData.setData('text/plain', spec);
  e.preventDefault();
}, true);

document.execCommand('copy');

The same listener handles Cmd/Ctrl+C while a selection is pinned, unless you have text selected or a field focused. In that case the copy is yours.

A spec an AI assistant can use

Version 1.1 adds a third copy format, "For AI". It is the text spec with colours and font families added, plus a short key that explains the notation:

UI spec measured from a rendered web page with Mikron. Sizes are in CSS px and come from the live layout, so treat them as exact.

Page: dabarov.github.io/mikron
Selection: 464 × 73
Inside: section#try.try › div.stage › article#card.card › ul.list

```text
li.row — 464 × 73 · padding 16 · gap 12
  span.status.bad — 3 × 40 · radius 1.5 · bg rgb(229, 72, 77)
  span.icon — 40 × 40 · radius 10 · bg rgb(31, 31, 31)
  div.meta — 256 × 40 · gap 4
    span.name "Relay" — color rgb(242, 242, 243) · font 16px/20px 500 -apple-system
    span.state.bad "Connection lost" — color rgb(229, 72, 77) · font 14px/16px 400 -apple-system
  button.action "Reconnect" — 97 × 32 · padding 0 12 · radius 8 · bg rgb(28, 28, 28) · color rgb(255, 255, 255) · font 14px/20px 500 -apple-system
```

How to read the spec:
- One line per element. Indentation is DOM nesting. The name is the tag with its #id and .classes, then the visible text in quotes.
- "W × H" is the border-box size of the whole element.
- padding and radius are in CSS shorthand order (top right bottom left; radius starts at the top-left corner).
- gap is the space between the element's children ("x / y" when the two axes differ).
- font is size/line-height, weight and family. bg and color are computed values.
- "×N" after a name means N identical siblings in a row. "(partial)" means the selection cut through the element.

A model that reads a screenshot has to estimate spacing. This gives it measured values and tells it how to read them.

The demo runs the real code

The project page lets you Shift + drag without installing anything. It is not a reimplementation: a build script concatenates the extension's content scripts into one file and puts a small stand-in for the chrome API in front. If the real extension is installed, the page's copy steps aside so nothing is drawn twice.

Tests

There is no build step and no framework, so the safety net is the test suite: Playwright cases that run against the unpacked extension in a real Chromium. They cover the gesture, the scanner, the drawing, the copied spec, the popup and this website.

What it does not do

  • It works in the top frame only. An iframe is drawn as one box.
  • Canvas and video are one box with a size.
  • It needs a mouse or trackpad. There is no touch gesture.
  • It is a Chrome extension. Other browsers are not supported yet.

Mikron is free, makes no network requests and has no analytics.
